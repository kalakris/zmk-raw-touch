The first release of zmk-raw-touch: a ZMK module that sends a keyboard
trackpad's finger position and contact state to a host application over
USB or Bluetooth, so that [RawTouch](https://github.com/kalakris/rawtouch)
can produce trackpad-style scrolling on macOS. Without the app, the
keyboard keeps pointing and wheel-scrolling on its own (Standard mode).

## What is in it

- A `zmk,raw-touch-pad` devicetree node that registers a trackpad,
  derives pointer movement from its absolute samples, and optionally
  detects taps in firmware.
- A second USB HID interface and a second Bluetooth HID service carrying
  touch samples while a host holds the stream lease (RawTouch mode).
- Input processors: a scroll marker (`zip_raw_touch_scroll`), an idle
  filter (`zip_raw_touch_idle_filter`), and a sample-time stamp for pads
  on a split peripheral.
- The wire format, protocol 4:
  [`docs/protocol.md`](https://github.com/kalakris/zmk-raw-touch/blob/v0.1.0/docs/protocol.md).

## Requirements

- A ZMK 0.3 / Zephyr 3.5 tree. Tested on MoErgo's ZMK `v26.09`, which
  CI also builds, with the Go60 in its stock split roles.
- The trackpad driver
  [`kalakris/cirque-input-module`](https://github.com/kalakris/cirque-input-module)
  `v0.1.0`, in absolute mode. It replaces the Pinnacle driver your tree
  imports.
- For RawTouch mode: RawTouch 0.1 on macOS 13 or later.

## Install

Go60 owners: use the
[Go60 configuration](https://github.com/kalakris/go60-rawtouch-config),
which has prebuilt firmware and steps for building with your own keymap,
including one made in MoErgo's Layout Editor. Other keyboards: follow the README's
[Setup](https://github.com/kalakris/zmk-raw-touch/blob/v0.1.0/README.md#setup).
Pin `revision: v0.1.0` for both the module and the driver in
`config/west.yml`, or use `stable` to follow releases.

- **Flash both halves of a split keyboard from the same build.**
- **Bluetooth hosts must forget the keyboard and pair again** after this
  firmware is first installed: clear the bond on the keyboard
  (`&bt BT_CLR`) as well. macOS keeps the old HID report map otherwise,
  and RawTouch mode does not work over Bluetooth. USB needs nothing.

## Known limitations

- One finger per pad; multi-touch gestures are not sent.
- Zephyr's USB device stack only; `USB_DEVICE_STACK_NEXT`, ZMK `main` and
  Zephyr 4.1 need a port.
- Rarely, a pad does not respond after power-on. Switch that half off
  and on again.
- The firmware reports its version to the host as major.minor, so
  RawTouch announces new minor releases of the module but not patch
  releases.
- Not yet tested: keyboards other than the MoErgo Go60, upstream ZMK
  `v0.3`, battery life, and deep sleep and wake. Reports are welcome.
